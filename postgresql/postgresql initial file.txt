		4. Cardinalidad
			Cardinality = cantidad de valores distintos en una columnas (or combination of columns).
							High cardinality → muchos valores unicos
							Low  cardinality → pocos valores unicos
			
			La cardinalidad importa porque afecta a como el performance engine construye el Plan de Ejecucion.
			Decide si use Index Seek or Scan or Nested Loop, etc
		
		5. Selectividad
			Cantidad de filas que se filtran en un WHERE or HAVING, etc
			
		6. Nested Loops
			. Combina filas de dos entradas
			. Para cada fila de la entrada externa (superior), SQL Server busca filas coincidentes en la entrada interna (inferior).
			. Lo usa cuando tenemos:
				Inputs chicos
				Alta selectividad
				
				SELECT *
				FROM Orders o
				JOIN Customers c ON o.CustomerID = c.CustomerID
				WHERE o.OrderID = 10248;

				Typical plan:

				Outer: Orders (1 row)
				Inner: Customers (Index Seek per row)

		10. Isolation Levels
			
			•	READ UNCOMMITED = El menor tipo de aislamiento. Permite leer data que no fue comiteada.
				o	Permite (dirty) data 
				o	No shared locks on reads
				o	Problems Dirty reads / Non-repeatable reads / Phantom reads

			•	READ COMMITTED (default) = Previene dirty reads - Solo lee data comiteada
				o	Shared locks are released immediately after Reading

			•	REPEATABLE READ - fuerte consistencia - No deja modificar datos leidos - Previene dirty reads
				o	Holds shared locks until transaction completes 
				o	Prevents rows from being modified after they are read
				o	Prevent – Dirty reads / Non repeatable reads

			•	SERIALIZABLE - El mas alto nivel de aislamiento - Previene todo dirty reads, nonrepeatable reads y datos fantasmas
				o	Transactions behave as if executed one after another 
				o	Uses range locks to prevent inserts into ranges being queried
				o	Prevents – Dirty reads / Non-repeatable reads / Phantom reads

			•	SNAPSHOT - Lee los datos como estan al comienzo de la TRX
				o	Row-versioning
				o	Reads a consistent snapshot of data as of transaction start 
				o	No blocking reads 
				o	Uses tempdb version store
				o	Prevents – Dirty reads / Non-repeatable reads / Phantom reads

			•	READ COMMITED SNAPSHOT - READ COMMITTED, but uses row versioning instead of locks
				o	Modern default option
				o	Variant of READ COMMITTED using row versioning instead of locks 
				o	Enabled at the database level
